# AgenticRAG: 项目动机与背景 (Motivation & Background)

## 1. 项目背景 (Background)

随着大型语言模型（LLM）的飞速发展，**检索增强生成（RAG, Retrieval-Augmented Generation）** 技术已经成为缓解大模型“幻觉”、引入垂直领域私有知识的行业标准。然而，在面对高度复杂的垂直场景——特别是**金融领域的深度问答**时，传统的单次检索（Naive RAG）暴露出明显的局限性：

1. **信息碎片化与跨文档关联**：金融研报、财报和新闻通常篇幅冗长且逻辑交织。回答一个复合问题往往需要从多篇不同的文档中抽取实体、数据，并进行跨文档的联合推理（Multi-hop Reasoning）。
2. **检索粒度与噪声干扰**：传统的 Chunk 向量检索在遇到相似度较高但语义不同的长尾数据时，容易召回大量无关噪声，导致 LLM 生成错误结论。
3. **多步规划缺失**：复杂的查询需要“步步为营”的解答策略（例如：先查出某公司的子公司，再查该子公司的近期财报数据）。传统 RAG 无法动态调整检索策略。

为了解决这些痛点，**Agentic RAG（基于智能体的检索增强生成）** 应运而生。本项目聚焦于金融多跳问答场景，旨在构建一个具备自主规划、工具调用、多步检索与自我验证能力的端到端 Agentic RAG 系统。

---

## 2. 项目动机 (Motivation)

本项目的核心动机不仅仅是构建一个复杂的工程系统，更在于探索**如何通过系统化的训练流水线（SFT + RLHF）使大语言模型真正掌握 Agentic RAG 的能力**。具体动机包括以下三个维度：

### 2.1 突破单跳检索的瓶颈
我们希望打造一个具备“思考-行动-验证”闭环的系统。通过引入 LangGraph 驱动的多智能体架构（PEV：Planner-Executor-Verifier），模型不再是单向的“接收检索结果并生成”，而是能够主动：
- **规划（Plan）**：将复杂问题拆解为多个子问题。
- **执行（Execute）**：根据当前子问题，灵活调用多种检索工具（语义检索、关键词检索、知识图谱检索、甚至精准读取特定段落）。
- **验证（Verify）**：在生成最终答案前，自我审视已收集的证据是否足以回答原始问题，如果不足则重新规划（Replan）。

### 2.2 打造高质量的“端到端”开源复现包
当前开源社区中，虽然有许多关于 Agent 或 RAG 的框架，但鲜有涵盖从**数据合成、监督微调（SFT）到强化学习（RL）对齐**的完整端到端复现方案。本项目提供了一整套可落地的 Pipeline：
- **自动化的数据合成与过滤**：能够从无标注的金融语料中，合成高质量的多跳 QA 数据。
- **SFT 流水线**：通过将 Oracle（理想）推理轨迹转化为 ReAct 格式，引导模型初步掌握工具调用的范式。

### 2.3 探索基于 GRPO 的 Agent 强化学习对齐
本项目最核心的探索动机是**验证组相对策略优化（GRPO）在复杂推理与检索场景中的有效性**。
- 我们不满足于仅仅通过 SFT 让模型学会“表面”的工具调用格式，而是通过集成 `verl` 强化学习框架，利用多轮 Agentic RL 进一步对齐模型的行为。
- **多维度奖励机制（Reward Design）**：通过精心设计的奖励函数（覆盖检索召回率、忠实度、正确性、格式合规性等），强迫模型在面对复杂金融问题时，既要保证检索的精准性（减少幻觉和无效动作），又要确保最终回答紧扣证据（Grounded Answer）。

---

## 3. 核心目标与愿景

- **科研与验证**：验证基于多跳检索和强化学习的大模型是否能超越传统 RAG，在复杂金融语料上取得更高的准确率（Correctness）和忠实度（Faithfulness）。
- **工程落地**：提供一站式的脚本与工具箱，使得研究者和开发者可以快速基于自己的私有领域数据，复现一整套 Agentic RAG 的 SFT 与 GRPO 训练流程。
- **开源生态**：沉淀通用的多智能体编排模式（LangGraph PEV）、多路检索融合算法（Hybrid Search + Reranker）以及 LLM 裁判评估系统（LLM-as-a-Judge），反哺开源社区。
